# Comprobante nativo de transporte HTTP

El registro experimental `HTTPReceiptJournal` pasó el fixture aislado en macOS (run 40871645505). El bridge ahora admite reservas opcionales y observa el callback terminal de URLSession, pero los consumidores de Capri aún no las utilizan: no recupera ni libera operaciones bloqueadas. La integración de transporte y su fixture requieren una nueva ejecución en macOS; este entorno no dispone de Swift/Xcode.

El registro SQLite almacena únicamente el ID y dueño UUID canónicos y uno de tres estados: `active`, `terminal` o `cancelledBeforeStart`. No guarda URL, credenciales, cabeceras, cuerpos ni respuestas. La reserva y el tombstone usan inserciones atómicas; el callback sólo modifica la reserva activa con el dueño exacto. La escritura usa SQLite con sincronización FULL. El tombstone impide que un comando de bridge retrasado inicie una operación después de haberse cancelado antes de iniciarla.

Para integrarla, el mismo ID debe reservarse de forma durable antes de crear la tarea, y el estado `terminal` debe guardarse sólo desde `urlSession(_:task:didCompleteWithError:)`. `invalidateAndCancel()` no es comprobante terminal: [Apple documenta que la cancelación retorna inmediatamente](https://developer.apple.com/documentation/foundation/urlsessiontask/cancel()). Si el proceso muere antes del callback o éste no puede guardarse, el registro queda activo y bloqueado. Incluso tras `terminal`, el servidor podría seguir procesando la solicitud; sólo procede declarar el resultado incierto y pedir revisión humana, nunca afirmar que la operación no ocurrió.

Faltan validar el bridge nativo y conectar sus consumidores, las pruebas de cierres/reaperturas reales en WKWebView y la evaluación de cuota y archivo. El primer fixture cubre reapertura del registro, concurrencia, callbacks ajenos o tardíos, claves canónicas y cancelación antes del inicio. Un segundo fixture usa URLProtocol local para comprobar el callback terminal de URLSession; está pendiente de ejecución. Ninguno valida un iPhone. El workflow público de prueba compila la unidad y ejecuta el fixture sin secretos, firma, IPA ni artefactos.
